# API reference

Interactive documentation is generated by FastAPI:

- Swagger UI — <http://localhost:8000/docs>
- ReDoc — <http://localhost:8000/redoc>
- OpenAPI schema — <http://localhost:8000/openapi.json>

This file is the copy-pasteable version.

---

## Conventions

**Base path** `/api` for everything except `/health` and `/`.

**Authentication** Send the token from `POST /api/auth/login` on every other request:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Pagination** List endpoints take `page` (≥ 1) and `page_size` (1–100, default 10) and
return:

```json
{ "items": [], "total": 42, "page": 1, "page_size": 10, "pages": 5 }
```

**Errors** Every failure uses one shape:

```json
{
  "code": "not_found",
  "message": "Summary not found.",
  "details": {},
  "request_id": "a3f9c1e08b2d4a71"
}
```

| `code` | HTTP | Meaning |
|---|---|---|
| `validation_error` | 422 | Request body or query parameters failed validation |
| `authentication_error` | 401 | Missing, malformed, expired or revoked token |
| `permission_denied` | 403 | Authenticated but not allowed (e.g. not an admin) |
| `not_found` | 404 | Does not exist, **or** exists but belongs to someone else |
| `conflict` | 409 | Duplicate email, or an admin self-lockout attempt |
| `payload_too_large` | 413 | Upload exceeds `MAX_UPLOAD_SIZE_MB` |
| `unsupported_file_type` | 415 | Extension not supported, or bytes do not match it |
| `extraction_failed` | 422 | File is unreadable or has no text layer |
| `rate_limited` | 429 | Too many attempts from this IP; see the `Retry-After` header |
| `summarization_failed` | 503 | The model could not produce a summary |
| `internal_error` | 500 | Unhandled server error |

**Response headers** `X-Request-ID` correlates a response with its log lines;
`X-Process-Time` reports server-side duration in seconds.

## Authentication

### `POST /api/auth/register` → `201`

```json
{ "name": "Aakash Malipeddi", "email": "student@university.edu", "password": "StrongPass123" }
```

```json
{
  "id": "0f7c1e6a-3b52-4f0e-9d1b-2c9a7e5f4b31",
  "name": "Aakash Malipeddi",
  "email": "student@university.edu",
  "role": "user",
  "is_active": true,
  "created_at": "2026-08-30T11:42:07.481Z"
}
```

Password policy: at least 8 characters, including one letter and one digit. Emails are stored
lower case and must be unique. A `role` field in the request is ignored — new accounts are
always `user`.

**Errors** `409` email taken · `422` validation · `429` more than 5 registrations per hour
from one IP.

### `POST /api/auth/login` → `200`

```json
{ "email": "student@university.edu", "password": "StrongPass123" }
```

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_at": "2026-08-31T11:44:19.002Z",
  "user": { "id": "0f7c…", "name": "Aakash Malipeddi", "role": "user", "is_active": true }
}
```

**Errors** `401` wrong email *or* password (identical response either way, by design) ·
`403` account deactivated · `429` more than 10 attempts in 5 minutes from one IP.

The throttle is keyed on the client IP, never on the submitted email: keying on the account
would let an attacker deliberately lock a victim out of their own login. A `429` carries a
`Retry-After` header with the number of seconds to wait, and applies to correct credentials
too — otherwise the status code itself would reveal that a guessed password was right.

### `POST /api/auth/logout` → `200`

Revokes the session row for the presented token, so the token stops working immediately.

```json
{ "message": "Signed out successfully." }
```

### `GET /api/auth/me` → `200`

Returns the same user object as login.

## Documents

### `POST /api/documents/upload` → `201`

`multipart/form-data` with a single `file` field.

```bash
curl -X POST http://localhost:8000/api/documents/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@quarterly-report.pdf"
```

```json
{
  "id": "9b1e4c77-5a02-4d3e-8f6b-1c2d3e4f5a6b",
  "filename": "quarterly-report.pdf",
  "file_type": "pdf",
  "size_bytes": 284913,
  "page_count": 14,
  "word_count": 5218,
  "created_at": "2026-08-30T11:50:12.117Z",
  "extracted_characters": 32874,
  "text_preview": "Quarterly Report — Platform Operations …"
}
```

Validation covers the extension (`pdf`, `docx`, `txt`), the declared MIME type, the byte size
and the file's magic bytes.

**Errors** `413` too large · `415` unsupported or mismatched bytes · `422` empty file or no
extractable text (scanned PDFs — the platform does not perform OCR).

### `GET /api/documents` → `200`
Paginated list of the caller's documents.

### `GET /api/documents/{document_id}` → `200`
The document plus its full `extracted_text`. `404` if it is not yours.

### `DELETE /api/documents/{document_id}` → `200`
Deletes the row and the stored file.

### `GET /api/documents/supported-types` → `200`

```json
{ "types": ["docx", "pdf", "txt"], "max_size_mb": 10 }
```

## Summarization

### `GET /api/summaries/options` → `200`

Reports the live model configuration, which is how the UI knows whether it is talking to
FLAN-T5 or the extractive fallback.

```json
{
  "lengths": [
    { "value": "short",  "label": "Short (2-3 sentences)",           "target_words": 55 },
    { "value": "medium", "label": "Medium (one paragraph)",          "target_words": 130 },
    { "value": "long",   "label": "Long (detailed multi-paragraph)", "target_words": 260 }
  ],
  "backend": "flan-t5",
  "model": "google/flan-t5-small"
}
```

### `POST /api/summaries/text` → `201`

```json
{
  "text": "Artificial intelligence is reshaping how large organizations handle …",
  "summary_length": "medium",
  "title": "AI adoption in document workflows"
}
```

```json
{
  "id": "7d2f9a10-6b3c-4e58-9a71-0c8d5b2e1f43",
  "request_id": "3c5b8e21-4d7a-4f19-8b62-9e1a0d7c6b45",
  "summary_text": "Organizations increasingly rely on abstractive summarization …",
  "word_count": 118,
  "compression_ratio": 0.1642,
  "processing_time_seconds": 4.281,
  "model_name": "google/flan-t5-small",
  "backend": "flan-t5",
  "chunk_count": 3,
  "created_at": "2026-08-30T11:53:44.902Z"
}
```

`text` must be at least 200 characters after whitespace normalization.
`summary_length` is one of `short`, `medium`, `long` (default `medium`). `title` is optional —
it defaults to the first ten words of the input.

**Errors** `422` too short, blank or an unknown length · `503` model failure (the attempt is
still recorded with `status = failed`).

### `POST /api/summaries/document/{document_id}` → `201`

```json
{ "summary_length": "long", "title": "Q3 operations review" }
```

Same response shape. **Errors** `404` document not found or not yours · `422` no readable
text · `503` model failure.

### `GET /api/summaries/{summary_id}` → `200`

Adds the request context to the summary:

```json
{
  "id": "7d2f9a10-…",
  "summary_text": "Organizations increasingly rely on …",
  "word_count": 118,
  "compression_ratio": 0.1642,
  "processing_time_seconds": 4.281,
  "model_name": "google/flan-t5-small",
  "backend": "flan-t5",
  "chunk_count": 3,
  "created_at": "2026-08-30T11:53:44.902Z",
  "title": "AI adoption in document workflows",
  "summary_length": "medium",
  "source_type": "document",
  "document_id": "9b1e4c77-…",
  "document_filename": "quarterly-report.pdf",
  "input_word_count": 718,
  "input_preview": "Artificial intelligence is reshaping …",
  "my_rating": 4
}
```

### `GET /api/summaries/{summary_id}/download` → `200 text/plain`

Returns a formatted report with `Content-Disposition: attachment`:

```
CloudMLOps - AI Document Summary
============================================================
Title            : AI adoption in document workflows
Source           : quarterly-report.pdf
Summary length   : medium
Generated at     : 2026-08-30 11:53:44 UTC
Model            : google/flan-t5-small (flan-t5)
Processing time  : 4.28s
Original words   : 718
Summary words    : 118
Compression      : 16.4% of the original
============================================================

SUMMARY
------------------------------------------------------------
Organizations increasingly rely on abstractive summarization …
```

## History

### `GET /api/history` → `200`

Query parameters: `page`, `page_size`, `search`.

```bash
curl "http://localhost:8000/api/history?search=finance&page=1&page_size=6" \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "items": [
    {
      "id": "7d2f9a10-…",
      "title": "Quarterly finance review",
      "summary_length": "medium",
      "source_type": "document",
      "document_filename": "q3-finance.pdf",
      "summary_preview": "Revenue grew 12% quarter over quarter, driven mainly by …",
      "word_count": 118,
      "input_word_count": 718,
      "processing_time_seconds": 4.281,
      "my_rating": 4,
      "created_at": "2026-08-30T11:53:44.902Z"
    }
  ],
  "total": 1, "page": 1, "page_size": 6, "pages": 1
}
```

`search` matches case-insensitively against the title, the generated summary and the original
input text. Results are always scoped to the authenticated user.

### `GET /api/history/{summary_id}` → `200`
Same payload as `GET /api/summaries/{id}`.

### `DELETE /api/history/{summary_id}` → `200`
Deletes the summary, its request row and any feedback on it (cascading foreign keys).

## Feedback

### `POST /api/feedback` → `201`

```json
{ "summary_id": "7d2f9a10-…", "rating": 5, "comment": "Captured the argument exactly." }
```

```json
{
  "id": "b2c3d4e5-…",
  "summary_id": "7d2f9a10-…",
  "rating": 5,
  "comment": "Captured the argument exactly.",
  "created_at": "2026-08-30T12:01:55.310Z"
}
```

`rating` must be 1–5; `comment` is optional and capped at 1000 characters (a blank comment is
stored as `null`). Rating the same summary again **updates** the existing record, so the
platform average is not skewed by repeat submissions.

**Errors** `404` not your summary · `422` rating out of range or comment too long.

### `GET /api/feedback/summary/{summary_id}` → `200`
Array of feedback records for one of your summaries.

## Administration

All of these require `role = admin`; a normal user gets `403 permission_denied`.

### `GET /api/admin/users` → `200`
Query parameters: `page`, `page_size`, `search` (name or email), `role` (`user` | `admin`).
Returns a `Page[UserResponse]`.

### `PATCH /api/admin/users/{user_id}/status` → `200`

```json
{ "is_active": false }
```

Deactivating also revokes every active session for that user, so their current token stops
working on the next request. `409` if an administrator tries to deactivate themselves.

### `PATCH /api/admin/users/{user_id}/role` → `200`

```json
{ "role": "admin" }
```

Revokes the user's sessions so their next token carries the new role claim. `409` if an
administrator tries to remove their own admin role.

### `GET /api/admin/stats` → `200`

```json
{
  "total_users": 24,
  "active_users": 22,
  "total_documents": 61,
  "total_requests": 148,
  "total_summaries": 145,
  "failed_requests": 3,
  "average_processing_time_seconds": 3.914,
  "average_rating": 4.21,
  "total_feedback": 57,
  "total_words_summarized": 412883
}
```

### `GET /api/admin/usage?days=14` → `200`

```json
{
  "counts_by_type": {
```

## System

### `GET /health` → `200`

Used by the container health check and by AWS App Runner. Returns `status: "degraded"` rather
than failing when the database is unreachable, so the probe response can explain the problem
instead of the container crash-looping.

```json
{
  "status": "ok",
  "environment": "production",
  "version": "1.0.0",
  "database": "connected",
  "ai_backend": "flan-t5",
  "ai_model": "google/flan-t5-small",
  "model_loaded": true
}
```

## End-to-end example

```bash
BASE=http://localhost:8000

# 1. Register and log in
curl -sX POST $BASE/api/auth/register -H 'Content-Type: application/json' \
  -d '{"name":"Demo User","email":"demo@example.com","password":"DemoPass123"}'

TOKEN=$(curl -sX POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"DemoPass123"}' | jq -r .access_token)
AUTH="Authorization: Bearer $TOKEN"

# 2. Upload a document and summarize it
DOC=$(curl -sX POST $BASE/api/documents/upload -H "$AUTH" -F "file=@report.pdf" | jq -r .id)

SUMMARY=$(curl -sX POST $BASE/api/summaries/document/$DOC -H "$AUTH" \
  -H 'Content-Type: application/json' -d '{"summary_length":"medium"}')
SUMMARY_ID=$(echo $SUMMARY | jq -r .id)
echo $SUMMARY | jq -r .summary_text

# 3. Rate it, search for it, download it
curl -sX POST $BASE/api/feedback -H "$AUTH" -H 'Content-Type: application/json' \
  -d "{\"summary_id\":\"$SUMMARY_ID\",\"rating\":5,\"comment\":\"Very useful\"}"

curl -s "$BASE/api/history?search=report" -H "$AUTH" | jq '.items[].title'
curl -s "$BASE/api/summaries/$SUMMARY_ID/download" -H "$AUTH" -o summary.txt
```
